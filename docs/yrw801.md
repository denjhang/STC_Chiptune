# YRW801 (OPL4 Wave ROM) 技术文档

## 概述

YRW801 是 Yamaha YMF278B (OPL4) 内置的 2MB PCM Wave ROM，包含 175 个乐器采样。
ROM 存储在芯片内部，YMF278B 通过简单的地址回绕实现**无状态、无缝循环**。

## 两种实现的地址模型

ymf278b.c 和 ymfm_pcm.cpp 对 header 的字节解析完全一致，
但内部位置表示不同：

| | ymf278b.c | ymfm_pcm.cpp |
|--|-----------|--------------|
| 位置单位 | 采样索引 (16.16 fixed-point) | 字节地址 (32.16 fixed-point) |
| looppos | `header[3:4]` (16-bit, 采样偏移) | `header[3:4] << 16` (32-bit, 字节地址) |
| endpos | `header[5:6]` (16-bit, 2's complement) | `-int32(header[5:6]) << 16` (负值, 字节) |
| advance | `pos += step; pos(u16)` | `nextpos = curpos + step; nextpos(u32)` |
| fetch | `getSample(startaddr + pos)` | `getSample(baseaddr + (curpos>>16))` |

两种模型产生相同的播放结果。12-bit packed 采样每 1.5 字节，
所以 ymfm 的字节步进 0x8000 (= 半字节) 对应 ymf278b 的采样步进 0x8000 (= 半采样)。

## Wave Table 头格式 (12 字节/乐器)

```
偏移  位域              说明
0     [7:6]=bits        0=8bit, 1=12bit, 2=16bit
0     [5:0]             startAddr[21:16]
1-2   startAddr[15:0]   22-bit 起始地址
3-4   loopAddr[15:0]    16-bit 循环起始偏移 (从 startAddr 算起)
5-6   endAddr[15:0]     16-bit 2's complement, 终止地址偏移
7     LFO/VIB           颤音参数
8     [7:4]=AR [3:0]=D1R  Attack/Decay1
9     [7:4]=DL [3:0]=D2R  Decay Level/Decay2
10    [7:4]=RC [3:0]=RR   Rate Scaling/Release
11    [3:0]=AM            振幅调制深度
```

### endAddr 解码

endAddr 是 2's complement：
- `endAddr = 0` → 单次播放 (oneshot), 播放到 ROM 末尾
- `n_samples = (0x10000 - endAddr) & 0xFFFF`

### loopAddr

- 从 startAddr 后第 loopAddr 个采样处开始循环
- `has_loop = loopAddr < n_samples`

## PCM 采样格式

### 8-bit (bits=0)
1 字节/采样, signed 扩展到 16-bit: `sample = rom[addr] << 8`

### 12-bit packed (bits=1) — **最常用, 全部 175 个乐器都是此格式**

1.5 字节/采样 (3 字节 = 2 采样)

```
偶数采样 pos=0,2,4...:
  addr = startAddr + (pos / 2) * 3
  v = (rom[addr] << 8) | ((rom[addr+1] & 0x0F) << 4)   // 16-bit unsigned

奇数采样 pos=1,3,5...:
  addr = startAddr + (pos / 2) * 3
  v = (rom[addr+2] << 8) | (rom[addr+1] & 0xF0)        // 16-bit unsigned
```

**注意**: C 源码中 sample 是 `INT16`，高位自然带符号。
Python/其他语言中 `<<` 产生正整数，必须手动 sign-extend:
```
if v >= 0x8000: v -= 0x10000    // → 范围 -32768..32767
```

解码值范围: 12-bit signed 值放在 16-bit 高 12 位，即 -32768..+32748。

### 16-bit (bits=2)
2 字节/采样, big-endian: `sample = (rom[addr] << 8) | rom[addr+1]`

## 循环机制

YMF278B 用 u16 position + u16 stepptr 实现：

```
每帧:
  stepptr += step          // u16.16 fixed-point 步进
  while stepptr >= 0x10000:
    pos = nextPos(pos, stepptr >> 16)
    stepptr &= 0xFFFF

nextPos(pos, step):
  pos = (pos + step) & 0xFFFF
  if (pos + endAddr) >= 0x10000:    // 越界
    pos = (pos + endAddr + loopAddr) & 0xFFFF   // 回绕
```

**关键**: 循环是纯地址跳转，无编解码器状态。但 PCM 层面的接缝不一定连续。

### loop 接缝分析

loopaddr=0 的乐器（大量），循环回到 pos=0。但波形末尾和开头的 PCM 值可能不连续。

实测 #0 Piano: loop 接缝 delta=24224 (last=-24128, first=96)。
这说明 YMF278B 硬件在 loop 接缝处也有 PCM 跳变，实际由 envelope (attack→sustain) 掩盖。

**对试听的影响**: 直接循环播放时会有明显咔哒。解决方案:
1. 只在 sustain 阶段循环（跳过 attack），用 loopaddr != 0 的乐器
2. PC 端 crossfade 处理接缝
3. furnace 的做法: 由作曲家选择合适的 loop 点

## 线性插值

```
s0 = getSample(pos)
s1 = getSample(nextPos(pos, 1))
sample = (s0 * (0x10000 - stepptr) + s1 * stepptr) >> 16
```

## 频率计算

### YMF278B 硬件公式

```
calcStep(OCT, FNUM):
  step = (FNUM + 1024) << (8 + OCT) >> 3

调音用 (calcStep(0,0) = 0x8000):
  ROM 采样率 = 22050Hz
  YMF278B 输出率 = 44100Hz (= clock/768, clock=33.8688MHz)
  step=0x8000 → 每个输出帧前进 0.5 个 PCM 采样 → 2x 上采样
```

### furnace 的做法

```
PCM_FREQBASE = 402653184 (0x18000000)

NOTE_PCM(note) = tuning * 2^((note+3)/12) * (PCM_FREQBASE / chipClock)

// 带采样的 centerRate 校正:
off = sample.centerRate / globalCenterRate  // 通常是 1.0
freq = off * calcFreq(baseFreq, pitch, ...)

// freq → OCT + FNUM:
if freq >= 0x800:
  freqH = bsr32(freq) - 11     // bit scan reverse
  freqL = (freq >> freqH) & 0x3FF
  freqH = 8 ^ freqH             // OCT 取反
```

### MIDI note → step (简化)

```
semi = midi_note - orig_pitch
step = 0x8000 * 2^(semi/12)
```

其中 `orig_pitch` 是乐器在 C4=60 下的 MIDI 音符号。
YRW801 ROM 乐器的原始音高: furnace 默认 centerRate=8372 (≈ A4=440Hz 的 AMIGA 标准)，
对应 MIDI note ≈ 69 (A4)。

但实际上 YRW801 的乐器录制音高各不相同，没有统一标准。
VGM 文件中每个 note-on 命令携带 OCT+FNUM，乐器原始音高由作曲家决定。

## 乐器列表

175 个乐器: 0-127 = GM 旋律乐器, 128-174 = 47 套打击乐 Kit

### 存储统计

全部 175 个乐器均为 12-bit packed 格式。
ROM 前 12*175 = 2100 (0x834) 字节是 instrument table。

### 内存布局

```
0x000000 - 0x00083B:  175 × 12 字节 instrument table (header)
0x00083C - 0x0017FF:  间隙/未用
0x001800 - 0x1FFFFF:  PCM 采样数据 (密集排列, 互相重叠)
```

### 地址重叠 (正常设计)

YRW801 的 PCM 数据大量重叠，几乎每个乐器的 startAddr 都在前一个乐器的数据范围内。
YMF278B 通过 startAddr + endAddr 限定每个乐器的有效采样范围，不管其他乐器的数据。

例: #0 Piano sa=0x1800, #1 Bright Piano sa=0x183F — 两者共享同一段波形的不同片段。

**对提取的影响**: 单独提取一个乐器时，必须严格按 n_samples 读取，不能读取超出范围的字节，
否则会读到相邻乐器的数据（听起来像"夹杂其他乐器"）。

## 对 STC32G 的适配方案

### 方案: 简化 PCM 波表

YMF278B 的核心优势是**地址回绕循环，天然无缝**。
但 12-bit packed 解码复杂，MCU 可简化为:

1. **8-bit PCM**: 1 字节/采样, 解码最简单，`sample = rom[addr] << 8`
2. **16-bit PCM**: 2 字节/采样, 音质最好，但存储翻倍
3. **12-bit → 8-bit 预处理**: PC 端将 12-bit 降为 8-bit，MCU 只做 8-bit 解码

### 存储对比

| 格式     | 每采样字节 | 1秒@22kHz | 7乐器avg5KB |
|----------|-----------|----------|------------|
| ADPCM    | 0.5       | 11KB     | 2.5KB      |
| 8-bit    | 1.0       | 22KB     | 5KB        |
| 12-bit   | 1.5       | 33KB     | 7.5KB      |
| 16-bit   | 2.0       | 44KB     | 10KB       |

ADPCM 的 3 倍存储代价换来完美循环 + 更好音质。
对于 128KB Flash，7 个 8-bit 乐器约 35KB，可行。

### 循环实现

MCU 端只需:
```c
pos += step;
if (pos >= loop_end) pos = loop_start;  // 简化版
// 或完整 YMF278B endAddr+loopAddr 公式
```

无需 ADPCM 的 acc/step 状态管理。

### MoonSound 驱动 (moonsound.c)

MSX 端 MoonSound (OPL4) 的寄存器布局:
```
wave 写入: reg 0x7E (port), data 0x7F (port)
FM 写入:   reg 0xC4, 0xC5 (port 1), 0xC6, 0xC7 (port 2)

WT 通道寄存器 (per channel, 间隔 0x20):
  0x08+ch: wave 编号低字节
  0x20+ch: wave 编号高字节 (bit 0)
 0x38+ch: FN_H(4bit) | OCT(4bit)  — 注意 OCT 不取反!
  0x50+ch: TL (volume)
  0x68+ch: KEY_CTRL (bit7=KEY, bit6=DAMP, bit5=LFO_RST, bit4=CH, bits3:0=PAN)
  0x80+ch: LFO_RATE | VIB
  0x98+ch: AR | D1R
  0xB0+ch: DL | D2R
  0xC8+ch: RC | RR
 0xE0+ch: AM
```

### SootSound 的 OCT 不取反

ymf278b.c 中 OCT 取反 (`8 ^ octave_raw`), 但 SootSound 驱动
直接写 OCT 值: `octave = pitch / 0x600 - 8`。这和 VGM 中的行为一致。

### wave 编号 384+ = RAM 乐器

xm2ltm.c 注释明确说明:
- "The OPL4 only allows 128 custom waves at the same time, waves number 384-511"
- XM 格式的采样被转换后上传到 OPL4 RAM，wave 编号 384-511
- 每个 custom sample 对应一个 12 字节的 OPL4 wave header (存放在 RAM 中)
- 多个 wave 编号可以共享同一个 sample 数据

### ms_rom_headers[] — YRW801 ROM 完整 dump

xm2ltm.c 内嵌了 YRW801 的完整 instrument table 原始 hex 数据 (175×12 字节)。
这个数据与 ROM 文件解析结果完全一致，验证了解析正确性。

### XI 文件格式 (OpenMPT XIInstrumentHeader)

**重要**: XI 文件和 XM 内嵌乐器是**不同结构**。参考 OpenMPT `XMTools.h`:

```
XI 文件 (XIInstrumentHeader, 298 bytes header):
  offset 0:   signature[21]  "Extended Instrument: "
  offset 21:  name[22]       乐器名 (null-padded)
  offset 43:  eof            0x1A
  offset 44:  trackerName[20]
  offset 64:  version        u16 LE (0x0102)
  offset 66:  XMInstrument (230 bytes):
    +66:  sampleMap[96]      音符→采样映射
    +162: volEnv[24]         音量包络 (12 个 x,y 对, u16)
    +210: panEnv[24]         声像包络
    +258: volPts(u8), panPts(u8), volSus(u8), volLoopStart(u8), volLoopEnd(u8)
    +263: panSus(u8), panLoopStart(u8), panLoopEnd(u8), volFlags(u8), panFlags(u8)
    +268: vibType(u8), vibSweep(u8), vibDepth(u8), vibRate(u8)
    +272: volFade(u16), midiEnabled(u8), midiChannel(u8), midiProgram(u16),
          pitchWheelRange(u16), muteComputer(u8), reserved[15]
  offset 296: numSamples     u16 LE
  offset 298: sample headers (numSamples × 40 bytes):
    每个采样头 40 bytes (XMSample):
      +0:  length(u32)      采样长度 (字节)
      +4:  loopStart(u32)   循环起点 (字节)
      +8:  loopLength(u32)  循环长度 (字节)
      +12: vol(u8)          音量 0-64
      +13: finetune(i8)     微调 (-128..+127, 1/128 半音)
      +14: flags(u8)        bit0=forward loop, bit1=bidi loop, bit4=16bit
      +15: pan(u8)          声像 0-255
      +16: relnote(i8)      相对音高 (半音)
      +17: reserved(u8)
      +18: name[22]         采样名 (含 YRW801 tone 编号)
  然后: 采样数据 (delta-encoded PCM, 8-bit 或 16-bit)

XM 内嵌乐器 (XMInstrumentHeader, 263 bytes):
  offset 0:  size(u32)       头大小 (含自身)
  offset 4:  name[22]
  offset 26: type(u8)
  offset 27: numSamples(u16)    ← 注意! 和 XI 不同位置!
  offset 29: sampleHeaderSize(u32)
  offset 33: XMInstrument (230 bytes)
```

### centerRate 计算

XM/XI 标准基准频率 8363 Hz:
```
centerRate = 8363 * 2^((relnote + finetune/128) / 12)
```

relnote=0, finetune=0 → centerRate=8363 Hz (C-2 = MIDI note 24)

### 采样数据解码

16-bit 采样使用 delta 编码:
```python
next = 0
for i in range(n_samples):
    next += read_int16_LE()  # signed delta
    sample[i] = next
```

8-bit 采样类似:
```python
next = 0
for i in range(length):
    next += read_int8()  # signed delta
    sample[i] = next * 256  # 扩展到 16-bit
```
